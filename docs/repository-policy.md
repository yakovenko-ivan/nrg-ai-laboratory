# Repository and research-artifact policy

This Git repository contains the reusable **agentic laboratory layer**.  It is
not a container for a particular scientific campaign, raw simulation output, or
an NRG installation.

## Belongs in Git

The following are portable project source and should normally be committed:

- `AGENTS.md` laboratory policy;
- project-local Pi extensions and skills under `.pi/`;
- `nrg_analysis/`, `campaign_tools/`, and reusable `agent_workspace/` code;
- the controlled `agent_workspace/studies/_template/`;
- portable configuration and trusted policy files under `config/`;
- `config/laboratory.local.toml.example`, but never the real local file;
- tests and small deterministic test fixtures;
- documentation;
- generic software/campaign examples that do not contain results from an active scientific use case (for example `campaign_tools/examples/`).

## Does not belong in Git

The following are local research/runtime state and are ignored by default:

- the external NRG source checkout or build tree;
- NRG executables and copied NRG `task_setup` resources;
- `config/laboratory.local.toml`;
- active campaign definitions and generated campaign state under `campaigns/`;
- raw NRG case data under `runs/`;
- user-specific studies under `agent_workspace/studies/<study>/`;
- study results, figures, reports, logs, execution provenance, PIDs, locks, and
  stop-control files generated by active work;
- Python virtual environments, caches, packaging outputs, and editor state.

## Curated scientific results

A result does not become source-repository material merely because it is
scientifically valuable.  Raw or live results should remain in the research
workspace or an appropriate archival/data repository.

If a numerical fixture is needed to regression-test a reusable method, it should be deliberately reduced to a minimal synthetic/deterministic test fixture with enough metadata to explain its purpose.  Real campaign outputs should not be copied into the source tree merely to serve as examples.

## Why campaign definitions are local

A campaign definition represents a concrete scientific use case.  The trusted
campaign schema and generator belong in Git; the user's current sweep design
does not.  Consequently a clean clone may have no `campaigns/` directory at
all.  The laboratory discovery tools must treat that as an empty local registry,
not as an installation failure.

## Provenance versus portability

Runtime provenance may legitimately contain absolute paths, executable hashes,
process IDs, and other machine-specific facts because it records an experiment
that actually occurred on a particular machine.  Such generated provenance
belongs with the local/archived scientific record, not in this portable source
repository.
